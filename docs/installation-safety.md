# 安装位置、误装与卸载

## 面向用户的规则

| 包 | 安装位置 | 安装、卸载的含义 |
|---|---|---|
| `@herenfor/dsh-wsl` | Windows Desktop | 连接 Windows 与 WSL；卸载后恢复原生界面和路由 |
| `dsh-wsl-agent` | 由桥接自动部署到 WSL | 桥接的配套组件，用户无需重复安装 |
| `@herenfor/dsh-tune` 等普通插件 | 需要它的实际运行端 | 由对应包提供功能；复用模式可跟随源 profile |

用户不需要在 Windows、WSL 各安装一次桥接。误装时应当知道哪里错了、当前是否生效，以及怎样恢复；恢复不要求编辑 YAML 或删除会话。

## 防错与提示

1. 发布包的 `dsh.bundle.platforms` 只声明 `win32`，由支持该声明的官方管理器拒绝在 Linux 激活。
2. 入口在读取用户桥接配置、连接 WSL、注册路由或修改设置之前再次检查平台；即使旧管理器忽略声明，也抛出明确的安装位置错误，供官方失败详情显示，不启动桥接。检测不依赖发行版名称。
3. WSL 插件页检查和安装本桥接时，直接显示“此插件应安装在 Windows Desktop；当前未启动，可以安全地从 WSL 卸载”。路径、压缩包和别名在检查返回实际包名后也会校验。卸载和停用操作始终可达。
4. 源 profile 误装的 Windows 桥接包不会再次跟随到 `desktop-wsl`。
5. 只输入版本号时指出应填写完整安装目标。其他包、路径、git 来源仍交官方管理器验证。

Linux 模拟 Desktop 仅允许测试 HOME 中标记 `private: true` 的副本，并要求显式的假传输环境变量。发布包不会因用户配置自定义传输而绕过平台限制。

## 操作失败与恢复

同步是两个 profile 上的两个操作；一边完成不代表两边都完成。界面在列表和详情页都显示同步失败，不自动卸掉已可用的一边。版本清单值先转换成包含包名的安装参数；失败保留 stdout 和 stderr 的有界诊断，方便定位后重试。

官方管理器可能已下载错误平台的依赖，再拒绝激活。此时不声称“没有安装任何文件”，而应说明没有启用、可以移除。用官方卸载移除这份依赖后，原有会话和标准预设仍能使用，不要求用户手动修配置。

正常卸载仍使用官方管理器：桥接的作用域清理函数关闭连接，恢复模块图和原有路由；用户文件、会话、WSL 原本安装的 DSH 和普通插件不作为垃圾删除。进行中的任务仍遵守官方管理器的保护及重启要求。保留的环境选择和用户配置可供重装使用，不把停用、热重载或断线当成彻底卸载去清理。

`tuned` 预设由优化插件提供。卸载桥接时不擅自修改其默认值或历史会话的预设选择。远端报告中的旧包名覆盖、重复条目与缺失提供者已由使用端清理；不能把那次手动清理当成桥接已经具备所有第三方插件的配置迁移能力。

## 本机检查

```bash
node --test experiments/mirror/tests/*.test.mjs
scripts/assemble.sh
node scripts/check-installation.mjs /path/to/dsh/lib/bin.js /tmp/dsh-wsl-check
```

集成检查使用一次性 HOME、真实 DSH 管理器和两个 Host：误装拒绝、误装后卸载、新会话、原有会话、正确位置连接、卸载恢复与重装。Windows Desktop 在 Linux 测试中由私有副本模拟，不能将该结果写成真实 Electron 窗口或系统级 CUA 验收。测试结束清除临时 HOME 和进程；只在指定的仓库外目录保留当前结果。
